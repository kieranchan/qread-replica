2. What the stream is for  [code unless marked]
-----------------------------------------------
BookStream is NOT the membership/cloud channel (that is plain HTTP, docs/API.md). It is the link to a server-side
Legado-compatible book-source engine ("兼容层", the strings `兼容层初始化失败`/`兼容层错误`/`兼容层启动失败`):
the app ships the user's book source JSON (InitSession.bookSourceJson) and the server executes the rules (search, explore,
book info, TOC, content, login UI, actions, RSS) and sends results back. Because the server-side engine cannot do
everything alone (cookies, WebView, local cache, HTTP through the phone's IP), it also CALLS BACK into the app over the same
stream (section 4).

Client class: `Qread` in util/source/Qread.dart (+ util/source/qreadmsg.dart for the Dart-facing request functions; these
are different files from qread/qread.dart, which is the bound-backend websocket client `QreadWebsocket`).
The grcp/qread_listeners.dart (`QreadListeners`, 11 slots, size 0x60) and grcp/qread_models.dart (`SessionInfo`, size 0x8
with no fields; `ActionResponse` {bool success @0x7, String result @0xf}; enum `ConnectionStatus`) have NO surviving
method bodies in the snapshot (classes exist, all code was inlined/stripped). What can be said:
  - ConnectionStatus values (Smi index in the enum constants pp+0x159f0..): 0 disconnected [infer: initial],
    1 = status set when connect is called with isReconnect=true [code], 2 = set after "gRPC 连接成功" [code],
    3 = set when connect starts with isReconnect=false [code], 4 = set in the catch block (connect failed) [code].
    Names are not in the snapshot (the _Enum name field was stripped); suggested: disconnected, reconnecting, connected,
    connecting, error [infer]. Status is pushed through a notifier at Qread.field_f via 0x1f26e4 (QreadListeners instance
    [infer]).
  - local SessionInfo (qread_models) is constructed (0xdcdb0) from the server's SessionInfo and handed to the listener 0x1cb260;
    local ActionResponse {success,result} is constructed from ServerMessage.actionResult (0xdcee0).

3. Transport and session life cycle (Qread, 0xe09f2c connect)  [code]
---------------------------------------------------------------------
* Server address: `Qread.allocate` 0xe8347c does an HTTP GET to `http://scheduler2.qread.xyz/api/allocate` with query
  `t` (ms), `platform` (`ios`/`unknown`/... by Platform flags), `appid`, `user` (and `@yuedu`-tagged value), decodes JSON
  `{code, data:{ip:String, port:int}, msg}`; failure text `获取服务器失败: <msg>`. connect() (0xe0a4a0 wrapper -> 0xe09f2c)
  reads `ip` (String) and `port` (int) from that map.
* Channel: `ClientChannel(host=ip, port=port, options)` with `ChannelCredentials.insecure()` (field_7 = false: PLAINTEXT
  HTTP/2, no TLS), `connectionTimeout` 60 s (60000000 us), `idleTimeout` 3000 s (0xb2d05e00 us) [infer: field mapping],
  `userAgent "dart-grpc/2.0.0"`, default `backoffStrategy`, default `ClientKeepAliveOptions`, `CodecRegistry` (gzip).
  Per-call options: `CallOptions(compression: GzipCodec("gzip"), timeout: 60 s)` for stub creation; the actual stream is
  opened with `CallOptions(compression: gzip)` only. => the replica server MUST accept gzip-compressed messages
  (grpc-encoding: gzip) and may answer uncompressed.
* No auth metadata is sent. Identity travels INSIDE messages: every request has `userToken`; the session is opened by
  `InitSession{bookSourceJson, userId, userToken, isdubug}`:
    userId = hex(md5(utf8(isLoggedIn ? username : appid)))  (0xe0a698)   [code]
    userToken = the token string at Qread.field_7f (the account `tockenid`, or empty/appid for non-members [infer])
    requestId = Uuid v4 (new for every ClientMessage)
  Two session messages exist: `initSession`(10) and `initSession2`(180); 0xe0a698 prints "gRPC 发送 InitSession2" and picks one of
  the two oneof members depending on `Qread.source.field_1f == 3` [code branch; meaning infer: source type 3 = Legado-JSON
  source]. After InitSession the server answers `sessionInfo` (ServerMessage tag 10) which sets Qread.field_77 = true
  ("session ready"), see 0xdcd20.
* Heartbeat: timer every 20 s (Duration 20000000 us, 0xd9094 "gRPC 启动心跳定时器（间隔: 20秒）") calls the sender with a
  `Ping` (empty) -> server answers `pong{timestamp}` (log "gRPC 收到 Pong"); failure log "gRPC 心跳失败". The timer also
  disconnects when the app is in the background and not in TTS-listening mode ("gRPC 应用进入后台且非听书状态，断开连接")
  and reconnects on resume (`handleAppResumed` 0x1f271c is registered in `Common.appResumedCallbacks`: "gRPC 应用回到前台，恢复连接").
* Reconnect: on stream close ("gRPC 服务端流已关闭") or error ("gRPC 错误: [<code>] <msg>") the code schedules
  reconnect attempts (3 s delay, "gRPC 计划第 N 次重连..."), counter at Qread.field_b7; below 5 attempts -> another try, >= 5 -> give up
  (0xd8da4) [code].

5. What a replica needs
-----------------------
* To keep the book-source features working with the original client the replica server must implement BookStream exactly as above
  (h2c, gzip, requestId correlation, Ping/Pong 20 s, sessionInfo after InitSession, jsonResult/actionResult replies).
  The result payload formats of search/info/toc/content (JSON inside JsonMessage.json / ActionResponse.result) were NOT
  recovered here -- they are the Legado Book/BookChapter/SearchBook JSON shapes [infer]; check docs/MODELS.md and the callers of the
  jsonResult handler (0xdd06c 'searchBook'/'addBook' branches are only client UI commands).
* The scheduler (`/api/allocate`) is plain HTTP GET returning {code:0?, data:{ip,port}} [infer code==0 is success: same convention as UserApi].
* Open: exact usage of Qread.field_* beyond those named; which source types go through initSession vs initSession2; no
  authentication check is visible on the client other than userToken in messages.
